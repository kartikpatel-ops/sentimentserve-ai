# SentimentServe AI — Database Design

## 1. Database

SentimentServe AI uses **MongoDB** as its database.

Mongoose is used to define the schema and interact with MongoDB.

---

## 2. Main Collection

The backend defines a Mongoose model named:

```text
Review
```

The model is implemented in:

```text
Backend/models/Review.js
```

MongoDB stores the corresponding review documents.

---

## 3. Review Schema

| Field        | Type             |  Required | Description                             |
| ------------ | ---------------- | --------: | --------------------------------------- |
| `name`       | String           |       Yes | Customer name                           |
| `company`    | String           |       Yes | Company identifier                      |
| `rating`     | Number           |       Yes | Rating from 1 to 5                      |
| `text`       | String           |       Yes | Written customer review                 |
| `sentiment`  | String           |        No | Positive, neutral, negative, or pending |
| `confidence` | Number           |        No | AI-generated confidence value           |
| `topics`     | Array of Strings |        No | Detected review topics                  |
| `createdAt`  | Date             | Automatic | Creation timestamp                      |
| `updatedAt`  | Date             | Automatic | Last update timestamp                   |

---

## 4. Rating Validation

The schema restricts ratings to:

```text
Minimum: 1
Maximum: 5
```

---

## 5. Default Values

The schema defines:

```text
sentiment → "pending"
confidence → 0
topics → []
```

These defaults apply when values are not supplied.

During normal review creation, the backend supplies the AI-generated sentiment, confidence, and topics.

---

## 6. Timestamps

The schema uses:

```javascript
{
  timestamps: true
}
```

Mongoose therefore maintains:

```text
createdAt
updatedAt
```

---

## 7. Example Document

A stored review can conceptually look like:

```json
{
  "name": "Rahul",
  "company": "technova",
  "rating": 5,
  "text": "Great service and fast delivery.",
  "sentiment": "positive",
  "confidence": 75,
  "topics": [
    "delivery"
  ],
  "createdAt": "2026-01-01T00:00:00.000Z",
  "updatedAt": "2026-01-01T00:00:00.000Z"
}
```

The actual timestamp values are generated by MongoDB/Mongoose.

---

## 8. Database Connection

The backend connects using the environment variable:

```text
MONGO_URI
```

The application does not hard-code the MongoDB connection string.

---

## 9. Database Operations

The current backend performs:

### Create

```text
POST /api/reviews
```

Creates and saves a review.

### Read

```text
GET /api/reviews/:company
```

Retrieves reviews for a company.

### Sorting

Retrieved reviews are sorted using:

```javascript
createdAt: -1
```

Therefore, newest reviews appear first.

---

## 10. Current Database Scope

There is currently one application model:

```text
Review
```

There are no backend models for:

* User
* Account
* Authentication
* Business
* Recommendation
* Notification

Those can be added as the project expands.
